Masterpiece

An open-source pipe organ sample player supporting industry-standard sample sets. It builds the instrument's own console out of the set's definition — artwork, drawstops, keyboards, pedalboard — and plays it.

What it is

An instrument, not a mixer with stop names

Sampled pipe organs are distributed as large libraries: a recording of every pipe, plus an XML definition describing the instrument around them — how the console is drawn, which key reaches which pipe, what the couplers do, how the wind system is built.

Masterpiece reads those libraries and turns them back into a playable instrument. It is a fresh design rather than a fork. The console is the real one, so an organ looks and behaves like itself.

It runs as a standalone application and as a VST3, AU or LV2 plugin — the same engine either way.

The console

The same program, reading different libraries

Each organ above is a freely published sample library and is not part of this project. Nine of the ten are produced by Piotr Grabowski, the tenth by Augustine’s Virtual Organs. Full credits are on the attribution page.

Libraries that ship several console sizes offer them all; the chooser only appears when there is a choice to make. A set whose manuals are part of a photographed backdrop falls back to an on-screen keyboard instead.

Using it

What you actually do with it

Loading

A large library is tens of gigabytes and takes minutes off a slow disk, so it loads on its own thread: the window stays live and the estimate is built from the rate the load is actually achieving, not from a file count. Cancel takes effect at the next file and throws away what it had read — a half-loaded organ that plays some notes and silently drops others would send you hunting through your library.

Playing

Drawstops, pistons and expression shoes are where the builder put them. A key pressed with the mouse takes the same path as the same note arriving over MIDI. The meter shows what reaches the audio device — after the room, the organ's own level and the master fader.

Registering without artwork

Some libraries ship no console picture, and some ship sixty stops across two jambs you would rather not hunt through. The stop list is the same registration by another route, grouped by division.

Routing

No sample library says anything about audio routing, so this is yours to decide — like the MIDI mapping. Output pairs carry across organs; which rank goes where is saved per organ, because a rank number means nothing in a different instrument. A rank you never touch plays through the first pair, and in stereo the pairs are summed, so nothing disappears when you split them up.

Voicing

A rank adjustment and a single-pipe adjustment add, so pulling one sour pipe into tune does not throw away the trim you put on the rank it belongs to. A and B are two complete sets: make a change, swap, and hear it against what was there before — from memory the comparison always flatters whichever you heard last.

Your console

Which manual a key plays is decided by its MIDI channel, and no organ file can guess how your console is wired. Right-click a drawstop and move the real one to learn it. The sequencer pistons and page-turn actions get their own learn buttons, because the organ does not declare them and there is nothing on screen to right-click.

Getting back to an organ

A slot number is something a thumb piston can be mapped to; a file path is not. Combination sets are whole registration books — one for a recital, another for a service — and changing set saves the one you are leaving first.

What it costs

CPU and memory in one place. Simple WAV only bypasses every refinement at once for a machine that cannot afford them. Streaming holds only the head of each release tail and fetches the rest while it plays. Nothing here writes to disk on its own: changes apply immediately, and you choose afterwards whether to forget them, keep them for this organ, or make them the default.

What it does

Under the console

Standalone, or inside your DAW

The same engine ships as a standalone application and as a VST3, AU and LV2 plugin. As a plugin the organ is one instrument among others: sequence it, render it offline, put a convolution of your own room after it, or play it alongside strings and choir on separate tracks.

Streaming sampler

A full organ is tens of gigabytes because every pipe is a separate recording. Attacks and loops stay resident; each release tail keeps only its head in RAM and the remainder is fetched by a background thread into per-voice ring buffers while the note sounds. One set goes from 12.2 GB to 5.6 GB, and the rendered audio is identical sample for sample.

Wind model

For libraries that describe their own pneumatics, the wind system is solved as a physical one — compartments, bellows, valves, conduits, and the air each pipe draws. Pull a full registration and the pressure sags the way the real instrument does, so the tuning and the attack move with it instead of staying glassy.

Voicing, down to the pipe

Level and tuning per rank, and per individual pipe, which add rather than replace: pulling one sour pipe into tune keeps the trim on the rank it belongs to. A and B hold two complete sets for instant comparison. Both are a multiply and a ratio taken once when a note starts, so they cost nothing while it sounds and work with the DSP switched off.

Every pipe, its own recording

Attack, sustain loop, and a matched release tail crossfaded in rather than cut to, so a key release leaves the room's own decay behind. Transposed ranks are resampled with four-point interpolation.

Polyphony that fails gracefully

When voices run out the engine steals a decaying release first, then the oldest quietest note. A key you have just pressed is never taken, so a full chord under a full registration thins from the back rather than dropping what you played.

Couplers as a switch network

A key reaching a pipe is a walk through the instrument's own switch graph, not a checkbox — so couplers, sub- and super-octaves and unison-off compose exactly as the builder wired them. Thumb pistons, combinations with capture, general cancel, crescendo, and a sequencer stepping the generals.

Enclosure and tremulants

Enclosed divisions are filtered per box as the shades move, so an unenclosed division stays unenclosed. Tremulants modulate amplitude and pitch per pipe, which lets one chest wobble while another does not.

Historical temperaments

Equal, or one of eight historical temperaments, each generated from its own fifth-chain definition rather than transcribed from a table. A set naming a temperament nobody recognises is reported, never quietly played in equal.

Multi-channel routing

No sample library says anything about audio routing, so ranks are assigned to output pairs by you and saved per organ. In stereo the pairs are summed, so nothing disappears when you split them up.

Your console, learned

Every MIDI input device at once, each knowing which manual it is. Right-click a drawstop and move the real one to learn it. MIDI out lights the drawstops on a physical console, and a jamb display is driven over system exclusive.

Recording

A MIDI capture takes stop changes and shoe movements as well as notes, so a performance can be replayed through a different registration; the audio capture is what it sounded like. Both at once is the useful combination.

Building

CMake and a compiler

cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

Windows, Linux and Raspberry Pi are built in CI. The standalone application is the product; the plugin wrappers come from the same engine.

Credits

Written with four projects open alongside

Masterpiece is its own implementation, but it is much the better for them. None of their code is compiled in.

GrandOrgue

The shape of the voice engine, and the release-crossfade behaviour that stops a key release from clicking.

OdfEdit

The clearest available reading of the organ-definition format: which objects exist, how they link, and which of them a converter has to give up on.

rusty-pipes

Sample and loop handling, and a great deal of hard-won file-format knowledge.

HISE

The streaming design: per-voice ring buffers refilled off a background thread.
